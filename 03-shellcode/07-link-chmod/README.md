# Lab 07 — link & chmod System Calls

## 1. 학습 목표

Linux 파일 시스템과 권한 모델을 시스템 콜 수준에서 이해한다. 사용자 공간에서 파일에 대한 작업을 요청할 때 커널이 어떤 정보를 검사하는지, 파일 이름과 inode, 권한 비트가 어떤 관계를 가지는지 살펴본다.

## 2. link

```c
int link(const char *oldpath, const char *newpath);
```

`link`는 기존 파일에 대한 새로운 하드 링크를 생성한다. 새로운 파일 데이터 복사본을 만드는 것이 아니라 동일한 inode를 참조하는 디렉터리 항목을 추가한다. 일반적으로 다른 파일 시스템 간 하드 링크는 만들 수 없고, 디렉터리에 대한 하드 링크도 제한된다.

### 주요 확인 사항

- `ls -li`로 inode 번호 비교
- `stat`으로 링크 수(`st_nlink`) 확인
- 원본 파일명을 삭제한 후에도 하드 링크를 통해 파일에 접근할 수 있는지 이해
- 권한 및 파일 시스템 경계가 실패 조건에 미치는 영향

## 3. chmod

```c
int chmod(const char *pathname, mode_t mode);
```

`chmod`는 파일의 접근 권한 비트를 변경한다. 일반적으로 파일 소유자 또는 적절한 권한이 있는 프로세스만 변경할 수 있다.

### 권한 비트

| Value | Permission |
|---|---|
| 0400 | Owner read |
| 0200 | Owner write |
| 0100 | Owner execute |
| 0040 | Group read |
| 0020 | Group write |
| 0010 | Group execute |
| 0004 | Other read |
| 0002 | Other write |
| 0001 | Other execute |

`0755`는 소유자에게 rwx, 그룹과 기타 사용자에게 r-x 권한을 준다. `04755`는 여기에 SetUID 비트를 추가한다.

## 4. 시스템 콜 분석 포인트

- 시스템 콜 번호와 ABI 확인
- 파일 경로 문자열 주소 전달
- 권한 인자를 정수 비트마스크로 전달
- 성공/실패 반환값과 `errno`의 관계
- 파일 소유권, 접근 권한, 디렉터리 권한의 상호작용

## 5. 학습 정리

`link`는 파일 이름과 inode의 관계를, `chmod`는 권한 비트와 접근 제어의 관계를 이해하는 데 적합하다. 파일 시스템 관련 시스템 콜은 단순히 함수 호출만으로 결정되지 않고 커널의 권한 검사 및 파일 시스템 제약을 따른다.

이 항목은 시스템 콜의 원리와 구현 시 고려사항을 정리한 학습 노트이다.
