# Linux Permissions, UID/EUID and SetUID

## 1. 실습 목적

Linux는 사용자와 그룹을 기준으로 파일 접근을 제어합니다. 이 실습에서는 파일의 소유자, 그룹, 권한 비트를 확인하고 프로세스가 실제로 어떤 사용자 권한으로 실행되는지 살펴봤습니다. 단순히 `chmod` 명령을 외우기보다는 파일 접근 제어와 프로세스 자격 증명 사이의 관계를 이해하는 것이 목표입니다.

## 2. Linux 권한 모델

```text
-rwxr-xr--
 │││ │││ │││
 │││ │││ └┴┴─ other: r--
 │││ └┴┴──── group: r-x
 └┴┴──────── owner: rwx
```

- `r (4)`: 파일 내용 읽기, 디렉터리 목록 조회
- `w (2)`: 파일 수정, 디렉터리 엔트리 생성/삭제(디렉터리의 x 권한 등도 필요)
- `x (1)`: 파일 실행, 디렉터리 탐색

권한은 8진수로 표현합니다. 예를 들어 `755`는 소유자 `rwx`, 그룹 `r-x`, 기타 사용자 `r-x`를 뜻합니다.

| Octal | Symbolic | Meaning |
|---|---|---|
| 700 | `rwx------` | 소유자만 접근 |
| 644 | `rw-r--r--` | 일반 텍스트 파일에 자주 사용 |
| 755 | `rwxr-xr-x` | 실행 파일/디렉터리에 자주 사용 |
| 600 | `rw-------` | 개인 설정/비밀 파일 등에 사용 |

## 3. 주요 명령어

```bash
whoami
id
pwd
ls -l
stat sample.txt
chmod 644 sample.txt
ls -l sample.txt
chmod u+x script.sh
ls -l script.sh
```

`ls -l`의 첫 번째 필드는 파일 형식과 권한, 이후 필드는 링크 수, 소유자, 그룹, 크기, 수정 시각, 파일명입니다.

## 4. Real UID와 Effective UID

프로세스는 여러 종류의 사용자 ID를 가집니다.

- **Real UID (RUID):** 프로세스를 실행한 사용자를 나타냅니다.
- **Effective UID (EUID):** 많은 파일 접근 권한 검사에서 기준이 되는 사용자 ID입니다.
- **Saved Set-User-ID:** 권한 전환을 위해 저장되는 자격 증명입니다.

일반적인 프로그램은 RUID와 EUID가 같지만 SetUID가 설정된 실행 파일은 실행 시 EUID가 파일 소유자의 UID로 설정될 수 있습니다.

## 5. SetUID

`chmod 4755`에서 맨 앞의 `4`는 SetUID 비트입니다. 실행 파일의 소유자가 root이고 SetUID가 적용된 경우 프로그램이 높은 권한으로 실행될 수 있으므로, 파일 소유권과 프로그램 내부 입력 처리에 각별히 주의해야 합니다.

```bash
ls -l /usr/bin/passwd
stat /usr/bin/passwd
```

SetUID 실행 파일의 권한 문자열에는 소유자 실행 위치에 `s` 또는 `S`가 나타날 수 있습니다. 대문자 `S`는 SetUID 비트가 설정되어 있으나 실행 비트가 없는 상태를 나타냅니다.

## 6. 보안 관점

- 불필요한 SetUID 프로그램을 최소화합니다.
- 실행 파일 소유자와 쓰기 권한을 관리합니다.
- 외부 명령 실행 시 환경 변수와 경로를 신뢰하지 않습니다.
- 사용자 입력을 검증하고, 가능하면 권한을 낮춘 상태로 처리합니다.
- 권한 변경 전후에 `stat`, `ls -l`, `id`로 실제 상태를 확인합니다.

## 7. 학습 정리

파일 권한은 디스크에 저장된 객체에 대한 접근 제어이고, UID/EUID는 프로세스가 어떤 권한으로 행동하는지 결정하는 핵심 요소입니다. 두 개념을 함께 이해해야 Linux 권한 상승 취약점과 최소 권한 원칙을 올바르게 설명할 수 있습니다.
