# Lab Results & Learning Outcomes

실습 과정에서 확인한 실행 내용과 학습 내용을 명령어별로 정리했다. 출력 예시는 시스템 환경에 따라 달라질 수 있으므로 실제로 관찰한 값과 일반적인 출력 형식을 구분했다.

## Lab 01 — who

**목표:** 로그인 사용자와 터미널 세션 조회

**실습 흐름:** NASM 어셈블리 작성 → 바이너리 변환 → C 실행

**관찰한 결과:** 로그인 사용자와 `tty`/`pts` 세션 정보 출력.

**학습한 점:** `execve`의 경로 포인터, 리틀 엔디언과 스택 문자열 배치.

## Lab 02 — whoami

**목표:** 실행 사용자 확인

**관찰한 결과:**

```text
Shellcode size: 39 bytes
root
```

**학습한 점:** `jmp-call-pop`을 통한 문자열 주소 획득과 NUL 종료 처리. 잘못된 `\\X` 이스케이프를 `\\x`로 수정하면서 기계어 변환 오류의 원인을 파악했다.

## Lab 03 — cat /etc/passwd

**목표:** 실행 파일 경로와 파일 인자를 분리하여 전달

**관찰한 결과:** `/etc/passwd` 계정 정보가 여러 줄 출력됨.

**학습한 점:** `argv[0]`, `argv[1]`, `argv[2]=NULL`의 포인터 배열 구성.

## Lab 04 — cat /etc/hosts

**목표:** 다른 길이의 파일 경로를 인자로 전달

**관찰한 결과:**

```text
Shellcode size: 52 bytes
127.0.0.1 localhost
127.0.1.1 kali
```

위 내용은 확인한 주요 출력 줄이며 파일 전체 내용은 아니다.

**학습한 점:** 문자열 길이가 변경되면 널 종료 오프셋도 달라지므로 소스를 수정한 후 바이너리를 다시 생성해야 한다.

## Lab 05 — ps

**목표:** 프로세스 목록 조회

**진행 내용:** `ps` 바이너리, `dump_ps`, `out_ps` 생성 단계까지 진행.

**출력 형식:** `PID`, `TTY`, `TIME`, `CMD` 열로 프로세스 정보를 확인할 수 있다. 최종 C 실행 화면은 별도로 기록되지 않았다.

**학습한 점:** 기존 `execve` 구현을 새로운 명령에 적용하는 방법.

## Lab 06 — ps -aef

**목표:** 옵션을 포함한 명령 실행

**진행 내용:** `ps_aef.s` 어셈블리 소스 작성.

**출력 형식:** 프로세스 소유자, PID, PPID, 실행 명령 등의 상세 정보. 최종 실행 결과는 별도로 기록되지 않았다.

**학습한 점:** `argv[1]`에 옵션 문자열을 전달하는 방법과 데이터 오프셋 계산.

## Lab 07 — link/chmod

**학습 내용:** 파일 시스템의 하드 링크와 접근 권한 변경 시스템 콜. 구현 및 실행 내용은 [학습 노트](../03-shellcode/07-link-chmod/README.md)에 정리했다.

## 공통 학습 성과

1. NASM으로 x86 명령어를 작성하고 raw binary로 변환하는 과정 이해
2. `ndisasm`으로 기계어 바이트와 어셈블리 명령어의 대응 관계 분석
3. C 바이트 문자열과 실제 기계어 길이 비교
4. `execve`의 경로, 인자 배열, 환경 변수 포인터 구성
5. Segmentation fault와 잘못된 이스케이프 시퀀스의 원인 분석
6. 시스템 호출, 파일 권한, 프로세스 메모리 구조의 연결 관계 학습
