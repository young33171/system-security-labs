# Stack Memory & Buffer Overflow

## 1. 실습 목적

C 프로그램에서 함수가 호출될 때 스택 프레임이 만들어지는 과정과 지역 변수, 반환 주소의 배치를 살펴봅니다. 배열의 경계를 벗어난 쓰기가 발생하면 왜 예기치 않은 동작이나 프로세스 종료로 이어지는지 메모리 구조를 중심으로 이해합니다.

수업에서는 `stack_example.c`, `buf_ret.c` 등의 예제를 다뤘습니다.

## 2. 프로세스 메모리 구조

일반적인 Linux 프로세스의 가상 주소 공간에는 다음 영역이 존재합니다.

| 영역 | 역할 |
|---|---|
| Text | 실행 명령어가 들어 있는 코드 영역 |
| Read-only data | 문자열 리터럴 등 읽기 전용 데이터 |
| Data | 초기화된 전역/정적 변수 |
| BSS | 초기화되지 않은 전역/정적 변수 |
| Heap | 동적 메모리 할당 영역 |
| Stack | 함수 호출, 지역 변수, 반환 주소 등 |

실제 배치는 운영체제, 실행 파일 형식, ASLR, 아키텍처에 따라 달라집니다.

## 3. x86 함수 호출과 스택 프레임

전통적인 32-bit x86 함수 프롤로그는 다음과 같은 형태를 취할 수 있습니다.

```asm
push ebp
mov ebp, esp
sub esp, 0x20
```

- `ESP`: 현재 스택 최상단 위치를 가리킵니다.
- `EBP`: 프레임 포인터로 사용될 수 있습니다.
- `call`: 복귀할 주소를 스택에 저장한 뒤 함수로 분기합니다.
- `ret`: 스택에서 복귀 주소를 꺼내 실행 흐름을 되돌립니다.

단, 최적화 옵션에 따라 프레임 포인터가 생략되거나 배치가 달라질 수 있습니다.

### 스택 프레임 개념도

```text
높은 주소
+--------------------------+
| 함수 인자                 |
+--------------------------+
| 반환 주소                 |
+--------------------------+
| 이전 EBP                  |
+--------------------------+
| 지역 변수                 |
| 배열 및 임시 저장 공간    |
+--------------------------+
낮은 주소
```

이는 이해를 위한 단순화된 그림이며, 실제 컴파일 결과는 컴파일러와 옵션에 따라 다릅니다.

## 4. 버퍼 오버플로우의 원리

크기가 정해진 배열에 경계 검사 없이 더 많은 데이터를 기록하면 배열 바깥의 메모리를 덮어쓸 수 있습니다. 예를 들어 10바이트 배열에 11바이트 이상을 쓰면 경계를 벗어납니다.

이때 발생할 수 있는 결과는 다음과 같습니다.

1. 인접한 지역 변수의 값이 변경됩니다.
2. 프로그램이 예상하지 못한 분기로 진행할 수 있습니다.
3. 접근할 수 없는 메모리를 참조하면 Segmentation fault가 발생할 수 있습니다.
4. 보호 기법이 작동해 프로그램이 비정상 종료될 수 있습니다.

C에서 배열 경계를 벗어나는 동작은 정의되지 않은 동작(Undefined Behavior)이므로, 항상 동일한 결과가 나온다고 가정할 수 없습니다.

## 5. 주요 방어 기법

### Stack Canary
함수 종료 시 스택에 저장한 보호 값을 확인합니다. 손상 여부를 감지하면 프로그램 실행을 중단할 수 있습니다.

### NX / DEP
데이터용 메모리 페이지를 실행 불가능하게 표시합니다. 데이터 영역에 있는 명령어의 실행을 제한하는 데 도움을 줍니다.

### ASLR
스택, 힙, 라이브러리 등의 메모리 배치 주소를 무작위화하여 주소 예측을 어렵게 합니다.

### PIE
실행 파일의 코드 영역도 주소 무작위화의 영향을 받을 수 있도록 지원합니다.

### 입력 검증
복사 전 길이를 검사하고 목적지 버퍼 크기를 초과하지 않도록 설계하는 것이 근본적인 예방 방법입니다.

## 6. 디버깅 시 확인할 항목

```bash
file ./program
readelf -h ./program
readelf -W -l ./program
```

- 실행 파일이 32-bit인지 64-bit인지 확인
- 메모리 세그먼트 권한 확인
- 스택 프레임과 지역 변수 배치 이해
- 입력 길이와 실제 버퍼 크기 비교
- 보호 옵션에 따른 실행 결과 차이 해석

## 7. 학습 정리

버퍼 오버플로우는 단순히 입력 문자열이 길어서 발생하는 문제가 아니라, 프로그램이 메모리 객체의 경계를 올바르게 관리하지 못할 때 나타나는 메모리 안전성 문제입니다. 함수 호출 규약과 스택 구조를 이해하면 이러한 취약점의 원인과 방어 방법을 체계적으로 설명할 수 있습니다.
